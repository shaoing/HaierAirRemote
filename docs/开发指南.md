# 海尔空调手机红外开发指南

> 适用：用手机红外发射头（Android `ConsumerIrManager`）控制海尔空调
> 验证机型：海尔 KF-35G/NGA12（单冷 1.5 匹挂机，老款）
> 协议来源：IRremoteESP8266 官方库 ir_Haier 实现逆向自真实遥控器，本指南所有时序/帧结构均已实机验证
> 验证 APP：海尔空调遥控器.apk（versionCode 13，服务器 /root/haier_remote）

---

## 一、物理层关键参数（最重要，错一个空调就不理你）

| 参数 | 值 |
|---|---|
| 载波频率 | **38000 Hz（38kHz）**，占空比 1/3~1/2 |
| 前导（Pre-Header） | **3000µs 载波 + 3000µs 静默**（一组） |
| 帧头（Header） | **3000µs 载波 + 4300µs 静默**（注意：前导+帧头共两组，共 4 个脉冲！） |
| 位 0 | 520µs 载波 + **650µs** 静默 |
| 位 1 | 520µs 载波 + **1650µs** 静默 |
| 帧尾 | 520µs 载波后静默 |
| 位序 | **MSB 在前**，逐字节高位先发 |
| 帧间最小间隔（MinGap） | 约 150ms（连发两条命令时用） |

### ⚠️ 血泪坑（网上资料常见错误）
网上流传"海尔 NEC 变体"参数（3000+6250 单前导 / 1560、520 位宽）**是错的**，
用那个参数空调完全无反应。本项目 v1~v9 就是栽在这里。
也不要用标准 NEC（9000+4500）——空调帧是 72bit/112bit 长帧，不是 32bit。

## 二、两种协议（按遥控器型号区分）

| 协议 | 帧长 | 前缀字节 | 对应遥控器 | 本机型 |
|---|---|---|---|---|
| HAIER_AC | **9 字节 / 72bit** | **0xA5** | HSU07-HEA03（老款） | ✅ 就是它 |
| HAIER_AC_YRW02 | **14 字节 / 112bit** | **0xA6** | YR-W02 | 备选 |
| （新机型可参考）HAIER_AC176 | 22 字节 | byte0=0xA6，byte14=0xB7 | 新款遥控 | 未涉及 |
| （新机型可参考）HAIER_AC160 | 20 字节 | byte0=0xA6，byte14=0xB5 | 新款遥控 | 未涉及 |

**不知道目标空调是哪种？** 最快办法：两种协议各发一次开机帧，哪种"滴"一声就是哪种。
（海尔空调对不认识的协议直接忽略，不会误动作；但见第五节第 1 条——同一命令不要连发多帧。）

## 三、9 字节协议（HAIER_AC）帧结构

| 字节 | 位 | 含义 |
|---|---|---|
| 0 | 7-0 | 前缀 = **0xA5** |
| 1 | 3-0 | **命令码**（见表 A） |
| 1 | 7-4 | **温度**，存 (设定温度 − 16)，范围 0~14 → 16~30℃ |
| 2 | 4-0 | 当前时钟·**小时**（0-23） |
| 2 | 5 | 固定 = 1 |
| 2 | 7-6 | 上下摆风：00 停 / 01 上 / 10 下 / 11 **摆风切换**（按摆风键发 0b11） |
| 3 | 5-0 | 当前时钟·**分钟**（0-59） |
| 3 | 6 | **关机定时使能**（1=定时关生效） |
| 3 | 7 | 开机定时使能 |
| 4 | 4-0 | 关机定时·小时 |
| 4 | 5 | 健康（Health）标志 |
| 5 | 5-0 | 关机定时·分钟 |
| 5 | 7-6 | **风速**：00 自动 / 01 高 / 10 中 / 11 低（注意低速是 3！） |
| 6 | 4-0 | 开机定时·小时 |
| 6 | 7-5 | **模式**：000 自动 / 001 制冷 / 010 除湿 / 011 制热 / 100 送风 |
| 7 | 5-0 | 开机定时·分钟 |
| 7 | 6 | 睡眠标志 |
| 8 | 7-0 | **校验和** = 前 8 字节累加和 & 0xFF |

> 位序说明：C 位域从**低位**开始分配（如 byte1 低 4 位=命令、高 4 位=温度），
> 发送时仍是 MSB 在前逐位发。移植时最容易在这里翻车。

### 表 A：9 字节协议命令码（byte1 低 4 位）

| 命令 | 码 | 命令 | 码 |
|---|---|---|---|
| 关机 | 0x0 | 睡眠 | 0x8 |
| 开机 | 0x1 | **定时设置** | **0x9** |
| 模式 | 0x2 | **定时取消** | **0xA** |
| 风速 | 0x3 | 健康 | 0xC |
| 温度+ | 0x6 | 摆风 | 0xD |
| 温度− | 0x7 | | |

注意 0x4/0x5 未定义，健康=0xC 摆风=0xD（有些资料写 0xB/0xC 是错位一个）。

## 四、14 字节协议（HAIER_AC_YRW02）帧结构

| 字节 | 位 | 含义 |
|---|---|---|
| 0 | 7-0 | 机型前缀 = **0xA6**（Model A；另一批遥控是 0x59） |
| 1 | 3-0 | 上下摆风：0 停 / 1 最上 / 2 中 / 3 最下 / A 下 / **C 摆动** |
| 1 | 7-4 | 温度（设定值 − 16） |
| 2 | 7-5 | 左右摆风（0 中 / 3 左极限 / 4 左 / 5 右 / 6 右极限 / 7 自动），低 5 位未用 |
| 3 | 1 | 健康 |
| 3 | 7-5 | 定时模式：0 无 / 1 定时关 / 2 定时开 / 4 开→关 / 5 关→开 |
| 4 | 6 | 电源（1=开） |
| 5 | 4-0 | 关机定时·小时 |
| 5 | 7-5 | **风速**：001 高 / 010 中 / 011 低 / **101 自动**（自动是 5！） |
| 6 | 5-0 | 关机定时·分钟 |
| 6 | 6 | 强力 Turbo |
| 6 | 7 | 静音 Quiet |
| 7 | 4-0 | 开机定时·小时 |
| 7 | 7-5 | **模式**：000 自动 / 001 制冷 / 010 除湿 / 100 制热 / 110 送风 |
| 8 | 5-0 | 开机定时·分钟 |
| 8 | 7 | 睡眠 |
| 12 | 4-0 | **按键码**（表 B，告诉空调"按了哪个键"） |
| 13 | 7-0 | 校验和 = 前 13 字节累加和 & 0xFF |

> ⚠️ 送风模式 = **0b110（十进制 6）**。官方库源码旁边注释写着 "// 5"，那是过时的序号注释，
> 照抄 5 会发成非法值 0b101，空调不执行（本项目源码早期版本就犯过这个错）。

### 表 B：YRW02 按键码（byte12 低 5 位）

温度+ 0x00 / 温度− 0x01 / 上下摆风 0x02 / 左右摆风 0x03 / 风速 0x04 / **电源 0x05** / 模式 0x06 / 健康 0x07 / 强力 0x08 / 睡眠 0x0B / 定时 0x10 / 锁键 0x14 / 华氏切换 0x1A

## 五、定时功能原理（本指南核心，务必理解）

**海尔空调的定时是空调内置定时器，不是手机倒计时！**

- 每条帧的 byte2/byte3 都携带**当前时钟**（时+分），空调借此同步内部时钟；
- 设定时：发一条 **TimerSet(0x9)** 帧，帧内写"当前时钟 + 关机/开机时刻 + 使能位"，
  空调"滴"一声、面板亮定时图标，**之后到点由空调自己执行**；
- 取消：发 **TimerCancel(0xA)**，帧内定时使能位清零；
- 设完手机可以关机、断电、带走，完全不需要在场；
- 定时字段存的是**绝对时刻**（几点几分），不是时长。APP 端换算：
  `fireMin = (当前小时*60 + 当前分钟 + 定时时长*60) % 1440`；
- 时长上限 23 小时 59 分。

❌ 反面教材（本项目 v11/v12 走过的弯路）：用手机 CountDownTimer/AlarmManager 倒计时到点再发关机帧——手机被杀进程/锁屏/没电就失效，而且手机根本不该留在空调旁边。

## 六、Android 发射代码要点

```java
ConsumerIrManager ir = (ConsumerIrManager) getSystemService(Context.CONSUMER_IR_SERVICE);
if (ir.hasIrEmitter()) ir.transmit(38000, pattern);  // pattern 单位 µs, 偶数个元素
```

`pattern` 数组按"载波开、载波关"交替，**以载波脉冲（开）结尾，因此总元素个数为奇数**：
`{3000,3000, 3000,4300, 520,1650|650, ... 每bit两组..., 520}`
9 字节帧 = 2+2+144+1 = **149 个元素**；14 字节帧 = 2+2+224+1 = **229 个元素**

### 发送规则（都是实测换来的）
1. **一次按键只发一帧**。温度±是增量命令，连发 N 帧就加减 N 度（实测连发 4 帧按一下降 3 度）；
2. 不要同时广播两种协议的帧去"碰运气"——若目标机两种都认（少见），会执行多次；正确做法是首次配置时用开机帧探测确定协议，之后固定用一种；
3. targetSdk 28 即可（过高版本 transmit 权限策略变化）；
4. 部分华为/荣耀机型 `transmit()` 不抛异常但静默不发射：先反射 `ConsumerIrManager.mService.transmit(int,int[])` 做备份通道，或引导用系统"万能遥控"验证硬件；
5. Manifest 声明 `android.permission.TRANSMIT_IR` + `uses-feature android.hardware.consumerir`（required=false），无需运行时权限；
6. 发射时距离 ≤3 米、正对接收窗、避开强光直射。

## 七、开发新型号空调的建议流程

1. **看原配遥控器型号标签**（电池仓）：HSU07-HEA03 → 9 字节协议；YR-W02 → 14 字节；再新的有 176bit/160bit；
2. 查 IRremoteESP8266 支持列表（github crankyoldgit/IRremoteESP8266，src/IRprotocol.h 里 decode_type 枚举）；
3. **最稳路线**：ESP32 + IRrecv 抓原遥控器每个按键的 raw 波形，直接把 int[] 数组写进 APP，跳过协议实现；
4. 如果新机型用 176bit/160bit：结构与本文不同（双校验和、22/20 字节），参考官方 ir_Haier.cpp 的 `HaierAc176Protocol` union 布局，本文的时序（双前导 3000/3000+3000/4300，位 520/1650/650）和"空调内置定时器"思想仍然适用；
5. 调试技巧：APP 里显示发送帧的 HEX，与库生成结果比对；空调"滴"声 = 帧被接受，无声 = 时序/校验错。

## 附：本项目验证过的样例帧（9 字节，可用来做单元测试基准）

以上样例均基于：开机状态、制冷 26℃、自动风、空调时钟 22:30。

| 场景 | HEX | 说明 |
|---|---|---|
| 开机 | `A5 A1 36 1E 0C 00 20 00 C6` | 命令 0x1；byte2=36→时钟22+摆风位0+固定位1 |
| 温度+ | `A5 A6 36 1E 0C 00 20 00 CB` | 命令 0x6，温度仍为 26（26-16=10=0xA，在byte1高4位） |
| 定时关机 23:30 | `A5 A9 36 5E 17 1E 20 00 37` | 命令 0x9；byte3=0x5E→bit6定时使能+分钟30；byte4=0x17→23时+默认12被覆盖；byte5=0x1E→30分+自动风 |
| 取消定时 | `A5 AA 36 1E 0C 00 20 00 CF` | 命令 0xA；byte3 无定时位 |

比对注意：
- **时钟字段（byte2低5位/byte3低6位）随发送时刻变化**，不同时间抓的帧 HEX 必然不同，这是正常的；
- byte4 默认 0x0C（12 时）来自库的 stateReset 默认值，只有设定时才被覆盖；
- 校验和（byte8）= 前 8 字节累加取低 8 位，可自行验算。
